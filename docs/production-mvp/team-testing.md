# 制作团队本机测试

每人运行独立的 XM_Studio，使用自己的数据目录和模型配置。已保存的制作修改自动记录；每台安装自动保存独立标识，无需登录或上报电脑名。制作页不再展示测试身份填写和「可用／需修改」反馈面板。

1. 按剧本 → 拆解 → 资产 → 视频 → 成片制作。资产只编辑完整生图提示词。视频卡列出角色、场景、道具和仅声音人员；图片不足或本次未发送会明确标记。
2. 正常编辑并保存即可记录前后版本，包括拆解中的资产提示词、资产完整生图提示词、视频正文和人工完整视频提示词；恢复默认也会保留切换前后的值。相同内容重复保存不增加修改轮次。资产图片齐备后，点击「确认资产并编写视频提示词」会直接提交编写并进入视频页，无需再确认一次视频单元；顶部「视频」步骤在资产页执行同一动作。编写中只显示状态，完成后展示完整提示词；已有提示词直接打开，刷新沿用任务，失败需显式重试。视频仍需点击「确认生成视频」。
3. 核对完整提示词并保存后，再明确点击生成。资产卡片可单项生成／重生；视频可在卡片单独生成或重新生成；底部支持批量生成或重试失败项。全部片段就绪后停留在视频页供检查，底部改为「确认视频并合成成片」，点击后才开始合片并进入成片页。刷新、重启或单项重生成完成不会自动合片。提示词有未保存修改时先保存；重新生成保留其他片段。卡片不提供反馈和替换上传入口。生成结果由制作人员实际查看，不以编辑记录推断质量认可。
4. 完成测试，在项目管理页顶栏点击「导出修改记录」，选择项目后点击「下载 ZIP」；单集列表页会默认选中当前项目。解压后先看 `report.md`：按字段展示修改前后差异、重新拆解输入及其任务状态；`events.csv` 也保留完整 before/after，`events.jsonl` 为完整证据。导出包含所选项目全部单集的已保存记录、模板、真实请求和媒体清单；勾选「附上图片与视频」才加入文件。包只在本机下载，不自动上传。
5. 将各人的 ZIP 交给负责人；增量或重复导出均可汇总，按事件 ID 去重。保留原始 ZIP，以便核对证据。

旧项目首次接入会记录 imported_baseline；无法反推过去改过什么、谁改、耗时多少。已有素材照常使用。此前保存的测试身份和审阅记录保留在历史包中；新记录沿用本机身份信息，未填写的信息保持未知，不从系统用户名推测。当前包包含本项目采集以来的历史批次与模板摘要。

OpenAI 兼容文本调用的本机读取等待为 30 分钟（建立连接为 30 秒），给长思考模型留足时间。`gpt-6-astra` 在 Chat Completions 和 Responses 通道使用流式接收，完整结果到齐后才校验和保存；流中断、缺少结束信号或结构化输出截断不会保存为成功。此等待值不改变模型的思考强度，也不是整项任务的总时限。

如果仍报 `524` 和 `120-second Proxy Read Timeout`，表示供应商代理仍在 120 秒无数据后断开；本机不能覆盖该限制，流式也需要供应商在思考期间实际发送心跳或数据。需供应商调高代理超时或提供支持长思考流式的入口。查看任务错误后显式重试，刷新不会自动重提。

## 按原因重新拆解

在单集「拆解」页点击「重新拆解」，填写哪里拆错、希望如何调整，再提交。表格或资产提示词有未保存修改时，先保存；取消弹窗不会发起任务。

例如填写：「埃利亚斯佩戴的手链、脚链应归入人物的束缚形态，作为一个完整人物资产，不单独建立铁链道具。保留镜头中的束缚状态，并更新人物引用。」模型会同时接收剧本原文、当前拆解结果和本次原因，修订资产建议、外观和相关镜头引用。原因随本次任务保留，不会覆盖本集长期附加指令。

已有同一人物时，束缚形态登记在人物本体下，画面引用形态，台词仍归人物本体；首次出现且只有一种外观时，直接把服装及束缚写进完整人物资产。重拆不自动删除项目已登记资产及历史素材，也不生成图片或视频。结果仍需审查；确认覆盖已有正式脚本时，按页面列出的影响确认。

## 一次导入整部剧本

入口：**项目管理 → 查看单集 → 整部剧本**。在剧情项目中执行：

1. 点击「上传整部剧本」，上传 DOCX、TXT 或 MD，也可以直接粘贴全文。推荐把每集标题单独成行，例如「第一集 开始」「第2集 重逢」。
2. 点击「识别分集」，核对每集的标题、原集号、正文首尾和字数。需要时修改起始行、合并到上一集或添加分界；修改后点击「校验调整并预览」。没有识别出标题时会暂存为一集，须手动核对分界。
3. 点击「确认分集并保存全部」。整批追加到当前项目，旧集和素材保留；同样的原文和分界重复确认不会重复建集。保存到此为止，不会开始拆解。
4. 核对后点击「一键拆解全部集」。模型按集顺序处理，每次只提交一集；可离开页面，刷新后查看原任务进度。需要暂停时点击「当前集结束后暂停」。失败后先查看对应集错误，修正后显式继续剩余集。
5. 完成后点击各集链接逐集审查，再按原流程确认资产、生成图片、编写视频提示词和确认生成视频。整批拆解不会自动确认资产或生成媒体。

首个标题前的文字归入第一集；重复、倒序集号和空正文需要修正，缺号会提示核对。当前入口识别已有标题并由制作人员确认，不会按字数硬切，也不会自动推断无标题剧本的剧情分界。单次最多 1000 集。

导入集的「剧本」步骤只读，整本原文、派生集和原始上传均保留。修改全文时回项目页重新导入修订版，形成新的集，旧集不会被覆盖。保存尚未完成的编辑前离开页面会提示处理。

资产只在同一项目各集间共享。前集尚未确认的新资产只作为后集命名和外观建议，不自动登记；每集仍独立提出所需资产。批量运行期间不能新增、删除、调序、归档或修改源文件；项目设置、资产目录或前集草稿变更会在继续后集前暂停，核对后确认继续。已完成集不会自动重做。

提交显示「结果未知」时，系统只核对原任务，不提供直接重提；保留页面中的原任务记录，待任务状态查明后再处理。不要通过重新导入或重建项目来绕过未知状态。

## 负责人离线汇总

在 XM_Studio 根目录运行：

```sh
.venv/bin/python -m scripts.merge_production_feedback /path/to/packages/*.zip --output /path/to/feedback-report
```

输出 `report.md`、`summary.json`、`events.csv`、完整 JSONL、模板与已附媒体。`report.md` 展示每次人工保存前后差异；汇总区分文本零修改采用、媒体首版采用、修改字段、道具删补、同提示词重抽、改提示词重生、上传、裁切和版本切换。对象详情列出当前审阅与最后修改后新增媒体候选数。

跨电脑按样例／批次／模板／模型比较，本机按序号及父版本追溯，不依据电脑时间拼接编辑顺序。未审阅、审阅已过期、旧数据基线、未知提交单列，不计为成功；缺少媒体或未查看画面时不判断画面质量。

道具 B1 的离线固定样例位于 `fixtures/asset-rule-baselines/`，只验证规则衔接和文字保留。先收集同一批样例的真实修改，查看高频问题与原因，再改模板、另开批次复验。真实模型识别质量、画面质量和省修改效果以这轮数据为准。
