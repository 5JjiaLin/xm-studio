# 资产拆解、编辑界面与制作测试记录：ArcReel / XM_Studio 对比

调查日期：2026-11-05。原项目仅作只读比对，当前 ArcReel HEAD 为 `aeebacc7e`，与 XM_Studio 导入基线一致。用户本轮要求先规划，实施顺序见根 [plan.md](../../plan.md) 第 8 节；本文不代表功能已经实施。

## 结论

道具过多的直接缺口是**缺少“是否值得独立生成参考图”的判断标准**。当前两项目的 `shared/new_assets_rule.md` 完全相同：原文中尚未登记的角色、场景、道具可以进入 `new_assets`，提供 register/merge/derivative/skip 四种决定；skip 只举“一次性出场、无需固定外观”的情况。它没有说明：反复出现的场景陈设仍可以包含在场景图里，有动作接触的石柱也不一定需要单独出图。

XM_Studio F1～F4 增加了跨组动作/道具状态和叙事切点规则，但没有修改这份资产登记规则。不能把问题归因为 XM_Studio 新增了一套“提取所有名词”的算法，也不能声称换回原项目就能减少道具。

## 原项目的完整规则

[ADR 0092](../../docs/adr/0092-asset-identification-folds-into-script-plan.md) 将资产识别并入逐集脚本规划：输入当集原文与已有名字/别名/描述，模型同时输出单元和新增资产建议；创作者确认后，程序登记资产并重写引用。它没有单独的全书资产提取闸门。

| 环节 | ArcReel | XM_Studio 当前 | 对问题的影响 |
| --- | --- | --- | --- |
| 识别入口 | 当集 `reference_video_script_plan`，含源剧本和已有资产表 | 同一链路，增加 F2 的叙事/状态规则 | 不需要另建资产识别模型调用 |
| 新增资产策略 | `register`、`merge`、`derivative`、`skip`，模型填写 `reason` | 共享片段完全相同 | 两者都缺少独立参考图的必要性门槛 |
| 场景和道具边界 | 场景描述包含陈设，道具描述形制/材质；没有避免双重登记的规则 | 相同 | 一物既进场景描述又单独生图 |
| 参考图数量 | 每个单元服从模型 `max_reference_images` | 相同 | 能力上限不是“应该生成多少资产”的筛选依据；上限较大时不能抑制冗余 |
| 确认与登记 | `ScriptReviewService` + `resolve_new_assets`，按名处理决定 | 服务文件相同；登记器只额外传递人工 `generation_prompt` | 多出的资产不是前端自行补造 |
| 描述编辑 | 原审查组件展示资产描述/处理决定 | 制作页再加完整提示词，描述与完整提示词同时显示 | 同一内容出现两遍，修改入口有歧义 |
| 资产图生成 | 描述 + 风格/布局模板 | 默认同链路；人工完整提示词覆盖模板结果 | 隐藏描述要同时处理空描述的新建与恢复默认 |
| 视频资产显示 | 参考资产能力可复用 | 卡片显眼位置只有人物角度选择；最终预览成功后才有所有附件的文字列表 | 角色控件不是完整资产清单，预览未就绪时场景/道具不可见 |
| 修改记录 | 媒体版本、API 调用、时间线修订与 UI 刷新事件 | 已继承；尚无制作编辑前后版本的统一持久记录 | 能查生成产物，不能完整回答每次人工修改了什么、谁改、改后是否采用 |

## 当前测试项目的证据

对象：`proj-4bc708bf`，标题“测试”，第 1 集，剧本型 reference_video 路线。查询的是本机现有记录，没有运行 ArcReel 或提交新生成。

- `api_calls.id=101` 的真实拆解输入，模型 `MiniMax-M3.1-Flash`，已有角色/场景/道具表均为空；包含现行新增资产规则和 F2“叙事切点”。因此不是已有旧资产清单导致本次沿用这些道具。
- 当前保存的拆解草稿有 2 角色、1 场景、6 道具，共 9 项，全部 register。登记项目也是这 9 项。媒体版本记录可见 9 张资产图各 1 个版本及 8 个视频单元各 1 个版本。
- 拆解调用的 `last_provider_response` 未保存原始响应；当前草稿可能经历人工保存，因此下表称为“现存草稿依据”，不把它冒充不可变的模型初始输出。这正是新记录能力要补齐的缺口。

| 道具 | 现存草稿的登记依据 | 建议默认处理 | 保留的剧情表达 |
| --- | --- | --- | --- |
| 大玉台 | “固定场景陈设” | 纳入黑色石殿场景图，不独立生图 | 玉台及法阵仍在场景和镜头文字中 |
| 黑石柱 | 场景四面有柱，参与推撞动作 | 纳入场景图，作为稳定空间锚点 | 推撞同一根柱、沿柱瘫坐的动作保留 |
| 灯笼 | 挂在黑石柱上 | 纳入场景图 | 照明及位置保留，不必单独参考图 |
| 铁链 | 持续锁脚，有碰撞/拖行声 | 通常作为角色束缚状态及动作文字；有独立结构特写、解锁/断裂等要求时再独立 | 锁脚、声响、拖动连续性保留 |
| 破旧木箱 | 持续提在手里，未交代丢弃 | 普通手持物默认文字/角色参考；特写、开启、交接或特定造型有作用时再独立 | 仍提着木箱，不能为省资产删掉或擅自安排丢弃 |
| 银色纹饰针 | 掉落，并成为结尾凝视焦点 | 保留独立道具参考图 | 掉落位置、外观一致与后续再出现 |

这份剧本可用 **2 角色 + 1 场景 + 1 核心道具**作为候选方案；铁链/木箱经样例质量判断可上调，总计 4～6 项。它是设计建议，不是所有剧本的固定数量上限，也不是已验证的画面质量结论。现有项目与素材保留，优化影响后续拆解；存量的关系移除由用户显式保存。

“纳入场景图”不使用 `merge prop→scene`：当前 merge 只允许同类资产。应在初次规划时将陈设写入场景描述，正文用普通名词；已有草稿多余项走 skip/关系移除，移除 `@` 而保留文字。后台校验结构、同类关系与引用一致；语义判断由提示词与人工审查承担，不能用“包含柱/灯”的关键词黑名单自动删除。

## 界面精简需要同步处理的边界

1. 隐藏新增/已有资产的描述标签、文本框、卡片描述段及引导用户修改隐藏字段的提示，保留名称、类型/采用方式、完整生图提示词、保存、恢复默认和生成/替换。
2. 旧 `description` 保留作默认框架的初始材料，不等于继续展示第二个输入框。手改完整提示词只保存 `generation_prompt`，避免隐藏描述随旧表单回写覆盖新值。
3. 当前编辑器在空描述时不取预览，空文本时禁止编辑；后端草稿请求和生成输入也要求描述。手动新增资产只输入完整提示词必须可保存与生成，不能靠伪造描述绕过校验。完整提示词非空时准入应接受该创作输入；两者均空时明确阻止生成。
4. 没有初始描述/默认模板结果的新建资产，恢复默认不能把用户清回不可编辑状态；按“没有可恢复默认”处理。默认预览失败时，已有人工完整提示词仍可编辑。
5. 当前编写模型只拿到描述，改完整生图提示词中的外观后可能继续读到旧描述。后续编写需获得明确标注的当前人工资产创作文本，用于身份与形制理解；不要把其中白底、四视图布局或生图画幅当作视频镜头指令，也不能假装这就是模型已看到的图片事实。
6. 视频主按钮当前根据 `pending_authoring` 切换“编写视频提示词”和“确认提示词并生成视频”。新主按钮固定承担“确认生成视频”；未编写时禁用并给单独的“编写视频提示词”动作。编写完成后仍停在审查，不自动提交视频。

## 现有记录能复用什么

| 现有机制 | 已有事实 | 缺口/复用方式 |
| --- | --- | --- |
| [api_calls](../../lib/db/models/api_call.py:14) | 提交提示词、参数、输入附件、任务/集/目标、模型、成本与结果 | 用作实发证据；不记录每一次人工保存，不能代替修改历史 |
| [VersionManager](../../lib/artifacts/version_manager.py:82) | 图片/视频历史文件、当前版本、生成提示词、部分执行依据 | 引用其版本和文件摘要；上传替换/切换版本另加行为关联，避免复制另一套媒体文件 |
| [ScriptBatchEditor](../../lib/script/script_batch_edit.py:1) | 脚本聚合校验、版本冲突检查、可恢复提交 | 作为单元正文/时长/增删排序的权威记录入口；保存前后快照 |
| [时间线修订](../../lib/edit_timeline/model.py:199) | 不可变修订、作者、操作与父版本 | 如统计剪辑只作关联；本轮重点不扩展成片编辑功能 |
| [项目事件](../../docs/adr/0085-project-events-dual-source-registry-derived-projection.md) | 显式事件与只读快照差分用于刷新页面 | 不依赖它补录每次编辑，轮询可能错过中间版本，也缺完整前后内容 |
| 现有匿名身份 | 免登录本地单用户 | 不能区分测试人员；新增测试者代号和安装标识，不建设团队登录系统 |

用户已确认测试方式：**每人本机运行，再导出记录汇总**。记录必须携带安装标识、测试者代号、测试批次、应用/模板版本；合并按事件 ID 去重，本机事件按序列排序，不根据不同电脑的墙上时间强行拼出一个编辑顺序。
