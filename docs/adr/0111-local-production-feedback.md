# 0111：本机制作反馈与可恢复保存

状态：已采纳并实施，2026-11-05。范围：XM_Studio 的制作测试，G4/G5。

反馈不承担业务状态、媒体版本、队列或页面刷新职责。业务仍以 project/script JSON、VersionManager、api_calls 与原任务为准；反馈使用同一数据根的 SQLite，保存完整修订证据和独立对象链。安装标识、测试者代号、批次、样例在本机冻结，不推断电脑身份，不连接外部统计服务。

在已有领域锁内读取 before，SQLite 持久化准备记录后才写业务 JSON。复用正式文件事务的边界；嵌套事务只在最外层成功后完成事件，失败则按回滚后的文件判定。下次同资源写入、启动及导出恢复未完成准备记录：当前摘要等于 after 则完成，等于 before 则 aborted，其余 unknown；恢复绝不改业务文件。付费产物关联失败只保留准备记录，不能导致任务重新生成。

HTTP 成功保存使用 operation_id；相同 ID 不同载荷拒绝。内容相同不新增修订。反馈基线对旧内容标 imported_baseline，首次模型落盘标 model；拒绝草稿保留隔离属性，不能当采用。媒体复用版本文件和摘要，不复制媒体库；模板保存完整内置包及摘要，真实请求沿 task/api_call 关联。

资产的业务身份仍为名称；反馈对象链独立，可记录改名、合并、删除和重建。单元依据实际 unit_id，不按行号对齐重拆。文本批准与媒体质量审阅分别保存；未审阅或缺记录不得算零修改采用。

导出仅包含选定项目的事件、模板、请求证据及媒体清单，可显式附媒体；不导出数据库、配置、环境变量或凭据。离线合并按 event_id 去重并校验冲突；项目以安装标识和项目链区分，保留本机序号，不凭跨电脑时钟推断先后。

跨进程恢复通过持有的 owner 文件锁识别仍在进行的写事务，不读取到中间态就提前完成；进程退出后锁自动释放，再按实际摘要恢复。首次旧内容基线在原文件/版本锁内采集，避免和正式保存竞态。项目的 `.production-feedback-id` 仅作反馈实验标识，随删除项目恢复保留，同名重建重新产生；业务名称、unit_id 与引用语法均不改变。排队任务与 HTTP 保存冻结提交时的测试身份，嵌套模型保存继承。

媒体版本在记录时保存文件摘要；导出核对摘要，缺失或损坏不会附成有效媒体。付费产物遇到 SQLite 准备失败时，先将证据写到数据根 `production_feedback_pending/` 再保留原版本；恢复只补证据，不能重发生成。模板摘要来自进程实际加载的内置模板及引用片段。
